System Architecture Overview

The AI-Powered Smart Public Distribution System (PDS) replaces traditional manual food-grain estimation with data-driven predictive intelligence. The application operates as a three-tier architecture comprising a modern Glassmorphic HTML5/CSS3/JavaScript frontend, a Flask REST API backend integrated with Scikit-Learn/XGBoost ML inference engines, and a high-performance indexed MongoDB database.

1. Demand Prediction

Predicts monthly demand for Rice, Wheat, Sugar, and Dal across 5 districts using historical lag features ($t-1$), 3-month rolling averages, beneficiary family demographics, and seasonal holiday indices.

2. Thread-Safe Inventory

Prevents race conditions when multiple Fair Price Shops execute grain distributions concurrently using Python's threading.Lock to guarantee non-negative atomic deductions.

3. Anomaly Detection

Employs unsupervised Isolation Forest trees to isolate statistical anomalies in distribution quantities and draw frequencies without falsely calling them fraud before officer verification.

Mathematical Formulations

Inventory Shortage & Procurement Formulation

Shortage = Predicted Demand - Current Stock

If Shortage > 0, status = "SHORTAGE" and recommended_procurement = Shortage.
If Shortage ≤ 0 and Current Stock > 1.5 × Predicted Demand, status = "EXCESS".

Isolation Forest Anomaly Scoring Function

s(x, n) = 2^(- E(h(x)) / c(n))

Where $E(h(x))$ is the average path length of point $x$ over an ensemble of isolation trees, and $c(n)$ is the average path length of unsuccessful searches in a Binary Search Tree. Shorter path lengths imply earlier isolation (outliers).

Examiner Viva Questions & Answers

Q1: Why did you compare multiple ML models rather than picking just one?

In empirical machine learning, the No Free Lunch theorem dictates that no single algorithm is guaranteed to be optimal for every dataset. We rigorously benchmarked 4 algorithms: Linear Regression, Decision Tree Regressor, Random Forest Regressor, and XGBoost Regressor on an unseen test set using MAE, MSE, RMSE, and $R^2$. We serialized the best model using Joblib so the Flask API loads it at startup without retraining on every request.

Q2: How does the system handle concurrent transactions safely?

In real PDS depots, multiple Fair Price Shops disburse grain simultaneously. Without concurrency controls, race conditions can produce negative warehouse inventory. We implemented Python's threading.Lock inside InventoryService to serialize inventory verification and deduction atomically, guaranteeing that available stock is never oversold.

Q3: Why must an anomaly not automatically be called fraud?

Ethical and operational AI principles mandate human-in-the-loop governance. A cardholder withdrawing larger quantities could be collecting legitimate accumulated welfare entitlements or drawing during disaster relief. Labeling an outlier as "fraud" without verification risks wrongfully denying food grain to needy beneficiaries. Hence, the system flags suspicious activity with risk scores and understandable reasons for administrative officer review.

Q4: What data preprocessing and feature engineering steps were performed?

We engineered time-series lag features ($t-1$ previous demand and actual offtake), 3-month rolling averages, and festive holiday indicators (Pongal in January, Diwali in October/November). We employed a Scikit-Learn ColumnTransformer applying OneHotEncoder on categorical attributes (commodity, region) and StandardScaler on continuous features, strictly fitting the pipeline on the training split to prevent data leakage.
